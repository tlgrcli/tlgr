# tlgr v2 — command reference

Generated by `_consolidate/docs.py` from `command_tree.json` (version 1). 679 commands, 321 aliases, 94 v1 paths preserved, 1797 catalog features covered.

## Conventions

### Shape

```
tlgr [global flags] <noun> [<sub-noun>] <verb> [<target>] [<args>] [--flags]; paths are at most 3 levels.
```

### References

- `chat` — @username | peer id (-100… for channels/supergroups) | t.me/… | tg://… | me | saved
- `user` — @username | id | +phone | me
- `msg_id` — message id inside <chat>; a t.me message link is accepted wherever a <chat> <msg_id> pair is expected
- `topic` — --topic <id> on any message command; `chat topic *` manages them
- `variadic` — multiple ids are variadic positionals (message delete <chat> <id>...)

### Global flags

`--json`, `--plain`, `-a/--account`, `--results-only`, `--select`, `--dry-run`, `--yes/-y`, `--no-input`, `--flood-wait-max`, `-v`, `--redact`

`--redact` (cross-cutting): --redact (and `[defaults] redact = true`) never prints access hashes, file references, invite hashes or session tokens; they are replaced by `"<redacted>"`. Access hashes are never printed by default in any human output and only under `--json --no-redact`.

### List / search flags

`--limit/-n`, `--cursor`, `--all`, `--since`, `--until` — JSON is `Page[T] = {items, has_more, next_cursor, total}`.

### Send options (every "send something" command)

`--parse md|html|none`, `--entities JSON`, `--reply-to`, `--quote`, `--topic`, `--silent`, `--schedule`, `--send-as`, `--effect`, `--no-preview`, `--spoiler`, `--ttl`, `--protect`, `--typing`, `--typing-auto`, `--paid-stars`

### Files

`--file (repeatable, `-` for stdin)`, `--caption`, `--out`, `--stdout`

### Secrets

`--password-env (default TLGR_2FA_PASSWORD)`, `--password-stdin`, `--password-file`, `--token-env` — secrets are never taken as bare argv.

### Durations and timestamps

30s | 5m | 2h | 7d | forever; timestamps are ISO-8601 in, RFC-3339 UTC out

### Output envelope

- ids: `id`, `chat_id`, `user_id`, `msg_id`
- dates: `date (RFC-3339)`, `date_unix`
- mutations: `ok`, `already` (idempotent no-ops return `already: true`)
- pages: `Page[T] = {items, has_more, next_cursor, total}`
- spelling: args snake_case (chat, user, msg_id, topic), flags kebab-case (--reply-to, --send-as), output fields snake_case

### Vocabulary

Verbs come from STYLE §1. Two documented extensions: **accepted verbs** — `report`, `clear`, `check`, `accept`, `decline`, `convert`, `press`, `invoke`, `translate`, `link`, `status`, `test`, `reorder`, `post`, `end`, `discard`, `answer`, `query`, `catchup`, `typing`, `invite`, `share`, `preview`, `save`, `catalog`; and **protocol/lifecycle verbs**, which name a Telegram or daemon operation with no synonym in the list — `send-code`, `resend-code`, `verify-code`, `sign-up`, `qr`, `recover`, `reset-account`, `reset`, `logout`, `terminate`, `confirm`, `accept-qr`, `change`, `install`, `uninstall`, `restart`, `reconnect`, `save-state`, `replay`, `decode`, `ping`, `catch-up`, `difference`, `backfill`, `purge`, `upgrade`, `craft`, `apply`, `refulfill`, `authorize`, `verify`, `rate`, `signal`, `sync`, `pay`, `delete-history`, `share-phone`, `raise-hand`, `tos`, `whoami`, `capabilities`, `exit-codes`, `init`, `validate`, `path`, `keys`, `compose`, `summarize`, `transcribe`, `can-message`, `can-post`, `reply`, `nearest`, `dialog-status`, `hide-stories`, `mark-unread`, `rename`, `info`, `temp`, `retry`, `logs`, `floods`, `venue`, `stealth`, `retry`.
Every other non-vocabulary tail was renamed to `<sub-noun> <verb>` (see `renames` in `command_tree.json`).

Top-level nouns beyond STYLE's closed list:

- `giveaway` — giveaways and gift codes are a first-class GUI surface, distinct from `gift`
- `sync` — update-state / getDifference plumbing, distinct from the `catchup` unread digest
- `net` — network + data-centre diagnostics (ping, dc, usage), distinct from `proxy`
- `webhook` — outbound event delivery configuration, sibling of `events`/`watch`
- `passport` — Telegram Passport is its own GUI surface
- `completion` — v1 path (`tlgr completion bash|zsh|fish`) kept for compatibility
- `status` — v1 shortcut; a single top-level command, not a noun with verbs
- `watch` — v1 shortcut; a single top-level command
- `schema` — v1 shortcut; a single top-level command
- `stats` — alias-only shortcut onto `chat stats *`

Verb-first nouns (the noun is followed by the object, not a verb): `resolve`, `search`, `completion`, `schema`, `watch`, `status`.

### Cross-cutting contracts

- **media upload mirror** — `media upload` and `message send --file` share one contract: the same file flags, the same SendOptions, the same MediaInfo output.
- **reply markup** — `--reply-markup JSON` uses the schema defined by the bots/payments group; `message get --json` renders the same schema in `reply_markup`, so a button read back can be pressed with `bot press`.
- **sticker split** — `sticker set *` = installed sticker/emoji sets (server state); `sticker pack *` = authoring a set you own; `emoji set *` are aliases of `sticker set *`.
- **catchup vs sync** — `chat catchup` (v1) is the unread digest; `sync catch-up` is updates.getDifference plumbing.
- **takeout** — takeout lives under the `export` noun (account group). `daemon takeout *` are aliases.
- **rights vocabulary** — admin/banned rights keywords come from the groups_channels_admin group and are used verbatim by `chat admin promote`, `chat permission set`, `chat member restrict` and `bot default-rights set`.
- **privacy keys** — privacy keys/rules come from account_security_privacy and are used by `privacy set`, `privacy global set`, `story blocklist set` and `contact close-friends set`.
- **event types** — event type names come from updates_network_daemon (`events list`) and are the only values accepted by `watch --events`, `job add --on` and `webhook set --events`.

### Short flags

- `-n` — bound to --limit on list/search ops only; --dry-run has no short form (STYLE listed -n for both)
- `-y` — --yes
- `-a` — --account
